# 구독 뉴스레터 자동 발송 복구 (2026-11-12)

## 원인과 변경

- 실제 보낸편지함/받은편지함의 마지막 주간 보고서는 10/19 09:43 KST였다. 운영 53종목의 기업 전체 `reviewed`는 0이며, 기존 cron은 구독자 조회 전에 이 조건으로 발송0건 성공을 반환했다. 자동 일정 검증은 기업 전체 검토를 부여하지 않으므로 영구 보류되는 구조였다.
- 주간 메일에 쓰는 일정은 각 필드의 공식 원문·확인 시각과 **현재 값에 묶인 근거**를 요구한다. 철회·상장 완료·충돌·조회 실패 자료는 제외한다. 청약 진행에는 검증된 확정 공모가가 필요하다. 미검증 기업 소개·점수·등급·경쟁률·가격 밴드·주관사는 넣지 않는다. 원문이 확인된 선택적 공모가/환불일만 표시한다.
- 매일 07:00 KST GitHub 수집과 매주 월요일 09:35 KST Vercel 뉴스레터 예약은 유지했다. 발송 요청 중 별도 DART 수집/서버리스 파일 쓰기를 제거하고 게시된 데이터를 읽는다.
- 발송 대상은 원격 저장소에서 새로 읽은 ACTIVE 구독자다. 빈 목록과 장애를 구분하고 이전 캐시로 대체하지 않는다. 해지/인증 대기·더미 주소·중복을 제외하며 작동하는 수신거부 토큰을 요구한다. 운영 재신청도 새 원격 상태로 처리해 오래된 ACTIVE 캐시가 해지를 되돌리지 못하게 했다. 메일 미설정 시 자동 ACTIVE 전환을 제거했다.
- Resend는 유효한 접수 ID, SMTP는 해당 수신자의 실제 accepted 응답이 있어야 성공이다. 모의 성공을 제거하고 실패/불명/보류를 집계하여 비성공 HTTP를 반환한다. 확인 메일의 실패도 사용자에게 발송 완료로 안내하지 않는다. 개인정보·토큰·공급자 오류 원문은 결과와 전송 로그에 넣지 않는다.

## 구형 저장소 호환

- 실제 운영의 구형 `{ subscribers }` 응답도 모든 행 검증·명시적 오류 없음 조건으로 읽는다. HTTP200 오류 응답은 거부한다. 관리자 목록도 원격 조회 실패를0명 성공으로 표시하지 않는다.
- 원격 응답에서 토큰이 누락되거나 짧은 기존 구독자는 CRON_SECRET으로 정규화한 이메일에 수신거부 전용 HMAC-SHA256 서명을 만들어 링크를 복원한다. 기존 유효 저장 토큰은 보존하며 시트 스키마 변경이나 ACTIVE 승격을 하지 않는다. 서명 검증과 취소는 새 원격 목록을 사용한다. CRON_SECRET 교체 시 이 방식의 이전 링크는 무효가 되므로 함부로 교체하지 않는다.
- 구형 POST가 `{result:"success"}`만 반환하면 fresh GET에서 같은 주소·요청한 상태가 저장됐는지 확인한다. 인증/등록은 토큰도 일치해야 하며, 취소는 토큰 열이 없어도 상태를 대조한다.

## 실행과 진단

- `GET /api/cron/newsletter`는 기존 관리자/CRON_SECRET 인증을 그대로 요구한다. Vercel 표식만으로 인증하지 않는다. 실발송은 한국 월요일에만 실행한다.
- 인증된 `GET /api/cron/newsletter?dryRun=1`은 모든 요일에 이용할 수 있다. 메일 전송/구독자 변경/발송 예약 없이 저장소·발송 설정·수신 가능 인원·내용 유무·CRON_SECRET 설정 여부를 확인한다. 예약 인증이 없으면 503 `scheduler_not_configured`다.
- 공개 `GET /api/newsletter/preview?template=weekly`는 같은 내용 선택/렌더러의 샘플이다. 실제 구독자 토큰은 사용하지 않는다.
- 동시 전송 최대2, 새 전송 시작 예산195초, Resend30초/SMTP 전체45초 제한과 cron 최대300초를 둔다. 제한 때문에 남은 발송은 성공으로 감추지 않는다. 자동 재호출/추가 예약은 도입하지 않았다.

## 중복과 확인 한계

- KST 월요일 주차+정규화한 이메일 해시로 안정적인 발송 키를 만든다. Resend에는 Idempotency-Key, SMTP에는 고정 Message-ID를 전달하며 같은 인스턴스의 겹치는 요청·이미 수락/불명인 수신자를 보호한다.
- 영속 발송 원장은 추가하지 않았다. **SMTP Message-ID/메모리 guard는 다른 인스턴스 간 정확히1회 보장이 아니다.** Resend 키의 보존 기간은 [공식 문서](https://resend.com/docs/dashboard/emails/idempotency-keys)상24시간이다. 수락 여부가 불명한 Resend 요청을 SMTP로 다시 보내지 않는다. SMTP 시간 초과도 미접수로 단정하지 않는다.
- 메일 제공자의 수락은 받은편지함 도착과 다르다. 실제 다음 예약 실행, 수신함 도착 및 반송 여부는 별도로 확인해야 한다.
- 기존 Apps Script의 SUBSCRIBE/VERIFY/UNSUBSCRIBE 계약만 사용한다. 지원하지 않는 원장 action을 보내거나 ACTIVE를 일괄 승격하지 않는다.
