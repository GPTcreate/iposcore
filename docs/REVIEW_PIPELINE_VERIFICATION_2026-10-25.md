# 점수·여론 및 D-1 블로그 수집 검증

> 현행 정책과 운영 흐름은 [핵심 흐름 복구 기록](CORE_FLOW_RECOVERY_2026-10-25.md)을 따릅니다. 현재 저장소 작업 일정 설정은 KST 09:17·12:17·18:17입니다. 아래 본문은 당시의 검증 이력이며 예약 실행·배포 완료를 뜻하지 않습니다.

## 요청과 결과 범위

점수와 여론을 핵심 기능으로 보존하고, 청약 전날 수집한 블로그 원문을 상세 페이지 하단에 표시하는 흐름을 구현했다. 금융 검토와 블로그 수집은 독립 상태다. 실제 운영 배포·예약 작업 성공·AdSense 승인은 아직 확인하지 않았다.

## 기존 실패 원인

- 기존 웹 `getCollectedReviewsContext`는 HTTP 수집 대신 고정 작성자·제목·검색 링크로 리뷰를 만들었다. Python 수집 코드는 웹 파이프라인과 연결되지 않았다.
- 관리자 채널 설정은 React 메모리에서만 변경되었고 실제 수집기로 전달되지 않았다.
- 기존 서버리스 저장은 파일 쓰기 실패를 성공처럼 처리하고 다음 로드에서 원래 JSON을 다시 읽었다. EROFS 모의 실행으로 저장 소실을 재현했다. 실제 운영 로그를 열람했다는 뜻은 아니다.
- 기존 하루 한 번 오전 수집은 D-1 후속 게시글을 놓칠 수 있었다. 앞선 콘텐츠 보완에서는 이를 차단하며 리뷰 자체가 비어 있었고, 이번 변경에서 실제 수집으로 대체했다.

## 현재 흐름

1. `reviewChannels.json`에 실제 네이버/티스토리 홈·RSS 주소를 기록한다. 현재 유효 RSS 3곳, 최대12곳이다. YouTube는 미연결이다.
2. KST 청약 전날 종목을 선정한다. 해당 청약의 30일 전부터 청약 당일까지 발행된 글 중 종목명·별칭이 확인되는 글을 수집한다.
3. 채널별 RSS를 한 번 읽고 대상 글 본문을 확인한다. 직접 원문 URL·실제 발행자·발행/수집 시각·짧은 관련 문장·SHA-256을 저장한다. 본문 전체와 가상 리뷰는 저장하지 않는다. 해시는 보존 문장의 식별값이며 원문 진위를 보증하지 않는다.
4. 종목명과 명시적인 작성자 입장이 함께 확인되는 경우만 참여/관망/불참으로 분류한다. 다른 종목 의견·상충 문맥·부정의 중첩은 보류한다. 일정 언급만 있는 글도 원문 목록에 포함하지만 의견은 미분류다.
5. 종목ID+청약일별 스냅샷을 원자 저장하고 URL 중복을 제거한다. 전체 실패는 이전 성공 원문을 보존하고 모든 현재 의견을 제외한다. 부분 실패는 실패 채널의 이전 원문만 보존하고 그 채널을 현재 집계에서 제외한다. 정상 수집으로 실제0건이 확인되면 옛 글을 비운다.
6. `ReviewPanel`이 상세 하단에 원문과 표본·상태를 표시한다. 같은 블로그/작성자는 최신1편만 의견에 반영한다. 표본없음은 `null`이며 중립0%와 다르다.
7. 확인된 공시는 최대85점, 실제 분류 표본의 참여 비율은 최대15점이다. 표본이 없으면 공시점수만100점으로 환산하고 배지에 표시한다. 공시 근거가 미확인인 기존37개 금융 수치는 점수 보류를 유지하며 실제 블로그는 독립 공개한다.

## 영속 저장과 운영 연결

- 로컬: 관리자 인증 → `/api/reviews/collect` → JSON 원자 저장 → 공개 API/상세 재로드. 채널 추가/토글/삭제도 파일 저장 확인 후 응답한다.
- Vercel: 관리 화면 수집은 `preview-only`로 명시한다. 읽기 전용 배포 파일에 저장했다고 응답하지 않는다. 운영 채널 수정은 저장소 변경과 배포가 필요하다.
- 운영 수집 경로: 기본 브랜치 GitHub Actions가 KST12:17/18:17에 수집 후 `reviewSnapshots.json` 한 파일만 커밋한다. 기존 Vercel Git 연동이 해당 커밋을 배포해야 사이트에 반영된다. 예약 작업은 지연될 수 있다.
- 별도 DB나 유료 LLM을 추가하지 않았다. 새 워크플로는 저장소 `contents:write`와 기본 `GITHUB_TOKEN`을 사용한다. 브랜치 보호/Actions 권한/실제 Vercel 배포 성공은 운영 실행에서 확인해야 한다.
- 전체 수집 실패도 실패 메타데이터를 저장한 뒤 CLI 실패 종료로 표시한다. 워크플로는 그 실패 기록을 커밋할 수 있으며 작업 자체는 실패로 남는다.
- 기존 금융 동기화/뉴스레터 cron은 별도 경로다. 이번 블로그 검증으로 실제 이메일·Telegram을 발송하지 않았다.
