# 공모주 카드 누적 관리 및 점수 산정 정책 가이드 (Card Lifecycle Policy)

이 문서는 `iposcore.kr`의 공모주 카드 데이터 누적 관리 원칙 및 청약 단계별 점수 산정 표준을 정의합니다.

---

## 1. 카드 누적 관리 원칙 (Zero-Deletion & Cumulative Archive)

1. **과거 데이터 영구 보존**:
   - 새로운 달이나 신규 공모주가 추가되더라도 **기존 종목 카드를 절대 삭제하거나 덮어쓰지 않습니다.**
   - 초기 37건은 시작 데이터이며 전체 서비스의 고정 종목 수가 아닙니다. 이후 등록되는 종목도 같은 목록과 보존 원칙에 따라 누적합니다.
   - 상장이 완료되었거나 공모가 철회된 모든 종목은 `status: 'LISTED'` 또는 `isCancelled: true` 상태로 유지되어 서비스의 신뢰도와 히스토리 데이터 자산으로 누적됩니다.
2. **생애주기(Lifecycle) 상태 전이**:
   - `UPCOMING` (청약 예정) ➡️ 증권신고서 접수 후 대기 상태
   - `SUBSCRIPTION` (청약 진행 중) ➡️ 청약 시작일(`subscriptionStart`) 도래
   - `WAITING_LISTING` (상장 대기) ➡️ 청약 마감 후 상장일까지 환불 및 배정 완료 대기
   - `LISTED` (상장 완료 / 지난 공모주) ➡️ 상장일 시초가/종가 수익률 영구 기록

---

## 2. 청약 예정(UPCOMING) 종목 점수 산정 정책

1. **수요예측 전 조기 낙인 방지**:
   - 기관 수요예측(경쟁률, 의무확약) 발표 전인 종목은 수치가 0이라고 해서 감점하거나 'C등급(패스 권장)'으로 오도하지 않습니다.
   - 미발표·누락 수치에 중간 기대치나 임의의 70~80점 임시 점수를 채우지 않습니다. 기관 경쟁률 0 초과, 확약 0~100%, 유통가능 비율 0 초과~100%의 유효한 등록값이 갖춰지면 공개 산식으로 참고점수를 계산합니다. 공모가·희망 가격 범위는 해당 점수 산식의 입력이 아닙니다.
   - 정량 원점수는 경쟁률 최대 40점·확약 최대 25점·유통 최대 20점입니다. 실제 명시 의견 표본이 있으면 긍정 비율(%) × 0.15를 더해 최대 100점으로 계산하고, 표본이 없으면 정량 85점을 100점으로 환산합니다. 확약 0%는 유효한 입력이며 확약 원점수는 0점입니다.
   - 점수 산출 가능 여부와 원문 확인 여부를 구분합니다. 근거 확인 전에는 `등록자료 참고점수 · 검토전`, 점수 지표의 개별 공식 출처·확인시각 또는 전체 검토 기록을 갖춘 뒤에는 `공시 참고점수 · 공시 확인`으로 표시합니다. 공개 목록 전체를 검토 여부로 숨기지 않습니다.
2. **배지 표기 표준**:
   - 예정 종목에는 `청약 유의(패스 권장)` 대신 **`수요예측 발표 대기`** 또는 **`사전 심사 대기`** 배지를 부여합니다.
   - 수요예측 결과가 등록되면 같은 산식으로 점수와 S/A/B/C 구간을 계산하고, 원문 확인 상태를 별도로 표시합니다. 공시 접수 즉시 자동 반영이나 특정 시각의 최종 확정을 보장하지 않습니다. 청약 예정 상태여도 유효한 지표가 이미 있으면 참고점수를 표시합니다.

---

## 3. 사용자 탐색 경험(UX) 보존 원칙

1. **뒤로가기/백스페이스 탭 보존**:
   - 사용자가 '청약 예정', '상장 대기', '지난 공모주' 탭을 보다가 상세 페이지를 보고 뒤로가기(백스페이스 포함)를 눌렀을 때, 첫 화면 기본 탭으로 리셋되지 않고 **기존에 보던 탭이 100% 복원**됩니다.
   - `sessionStorage`와 URL `?tab=` 파라미터를 결합하여 브라우저 히스토리와 완벽히 동기화합니다.
