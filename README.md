# IPOScore — 공모주 일정·참고점수·원문과 배정·비용 계산

> 2026-10-25 현재 기준: 등록 종목의 일정·참고점수·실제 원문 탐색 흐름을 유지합니다. 초기 37건은 시작 데이터이며 신규 종목과 과거 카드는 동적으로 누적합니다. 공시 확인은 항목별로 표시하고, 유효한 등록 지표로 계산한 점수에는 검토 전 표기를 붙입니다. 목록 전체를 원문 검토 여부로 숨기지 않습니다. 현재 기준은 [`/methodology`](https://www.iposcore.kr/methodology)와 [카드 누적 정책](docs/CARD_LIFECYCLE_AND_ACCUMULATION_POLICY.md)을 참고하세요. 과거 작업·검증 경과는 [콘텐츠 보완 기록](docs/ADSENSE_CONTENT_REVIEW_2026-10-25.md), [수집 기능 검증 기록](docs/REVIEW_PIPELINE_VERIFICATION_2026-10-25.md)에 보존합니다.

공시를 읽는 방법과 균등·비례 배정, 증거금·대출이자·손익을 직접 비교하는 도구를 제공합니다. 운영 URL은 https://www.iposcore.kr 입니다.

## 🌟 주요 핵심 기능

1. **공모주 참고점수 (IPO Score)**
   - **공개 산식**: 기관 경쟁률 최대40 + 확약 최대25 + 유통비율 최대20 + 실제 명시 의견의 긍정 비율(%)×0.15점. 의견 표본이 없으면 정량85점을100점으로 환산하며 산출 기준과 표본 수를 배지에 표시합니다.
   - 기관 경쟁률>0, 확약0~100%, 유통가능 비율>0~100%이면 등록자료로 계산합니다. 공모가·희망 가격 범위는 산식에 없으므로 미확정이어도 점수를 숨기지 않습니다. 원문 확인 전에는 `등록자료 참고점수 · 검토전`, 점수 지표의 항목별 근거 또는 전체 검토 기록이 있으면 `공시 확인`으로 구분합니다.
   - 기관 경쟁률이 0인 미발표 종목이나 필수 지표 누락·오류는 발표·자료 확인 대기입니다. 무자료에 임의 평균값이나 70~80점을 채우지 않습니다. 공모가 상단 초과 가점도 사용하지 않습니다.
   - 아이엠기업인수목적1호의 점수 지표 1,266.52:1 / 0% / 95.42%에는 [DART 개별 원문](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20261022000373)과 항목별 확인시각을 연결했습니다. 명시 의견 표본이 없을 때 원점수45 ÷ 85 × 100을 반올림해53점이며, 이 표시는 다른 모든 항목의 검토 완료를 뜻하지 않습니다.
   - S/A/B/C는 비교 구간이며 수익 예측이나 청약 추천이 아닙니다. 구간표는 `/methodology`에 공개합니다.

2. **종목 요약과 실제 블로그 원문·의견**
   - 원문 확인을 대체하지 않습니다. 자동 생성 자료는 검토 완료로 승격하지 않으며, 검색 링크로 전문가의 의견을 만들어내지 않습니다.
   - 실제 RSS·본문에서 해당 종목이 언급된 짧은 근거와 원문 링크를 제공합니다. 명시 입장이 없으면 미분류로 남기며 무표본 비율은 `null`입니다. 유료 LLM 호출은 없습니다.
   - 원문은 canonical URL로 중복을 정리하고, 의견 표본은 동일 블로그·작성자의 최신1건에서 명시 입장만 집계합니다. 최근 수집에 실패한 채널의 보존 원문은 표시하되 현재 표본과 점수에서 제외합니다. 일부 실패이면 정상 수집된 채널의 표본만 반영합니다.

3. **인터랙티브 비례 청약 계산기**
   - 비례 경쟁률·증거금률·균등 주수·대출 원금·사용 일수·매도 비용을 직접 입력합니다. 기관 경쟁률로 비례 경쟁률을 추정하지 않습니다.
   - 손실 시나리오, 배정 가정, 손익분기를 비교하며 실제 배정을 보장하지 않습니다.

4. **구글 애드센스 최적화 슬롯 컴포넌트 (`GoogleAdSlot`)**
   - 소유권 확인 메타 태그와 ads.txt를 유지합니다. 관리자 페이지에는 광고 로더를 넣지 않습니다.
   - 광고는 `NEXT_PUBLIC_ADSENSE_ADS_ENABLED=true`와 실제 슬롯 ID가 있어야 활성화됩니다. 기본 광고 자리 표시와 가짜 슬롯은 제거했습니다.

5. **메일링(뉴스레터) 구독 시스템**
   - 매주 월요일 오전 8시 주간 공모주 캘린더 브리핑 발송.
   - 확인된 청약 자료가 없으면 주간 발송을 보류합니다. 실제 발송을 검증 목적으로 실행하지 않습니다.

## 🛠️ 기술 스택

- **프론트엔드/풀스택**: Next.js 16 (App Router, Turbopack), React 19, TypeScript, Tailwind CSS
- **아이콘**: Lucide React
- **블로그 수집 파이프라인**: TypeScript, fast-xml-parser, Cheerio, GitHub Actions → JSON 스냅샷 → Vercel Git 배포. 기존 Python/Gemini 코드는 보관용이며 웹 수집과 연결되지 않습니다.
- **이메일**: HTML 뉴스레터 템플릿 (Resend / Stibee 연동 가능)

### 공식 일정 검증

기존 예약 작업에서 공시 발견 후 공식 일정을 먼저 검증합니다. 동일 DART 접수번호는 캐시를 재사용하고 일정 임박도에 따라 6/24/72시간 간격으로 대상만 조회합니다. 회당12종목·HTTP30회로 제한하며 실패는 간격을 늘려 재시도합니다. 한국투자증권·IBK투자증권 최신 공지 어댑터와 DART 일정표를 지원하고 부분 추출·충돌·실패를 전체 일치로 표시하지 않습니다. 비공식 포털은 자동 보정하지 않습니다.

npm run verify:official -- --dry-run
npm run verify:official -- --write

확인시각만 달라지면 재배포하지 않으며 새 상장성과는 값과 연결된 공식 상장일 근거가 있어야 저장합니다. 세부 기준은 [공식 검증 운영 절차](docs/OPERATIONAL_INTEGRITY_PROCESS.md)를 참고하세요.

금융 갱신 단계는 청약이 끝났지만 상장 결과가 비어 있는 종목을 KIND 상장법인 목록과 대조합니다. 전체 목록 1회 조회로 정확한 회사명·시장·종목코드·실제 상장일을 확인하며, 코드와 상장일의 근거만 보완합니다. 시세는 회사명·코드·주식 종류가 일치하고 상장 당일 정규장 마감 후에만 저장합니다. 기존 시초가·종가가 모두 저장된 종목은 재수집하지 않습니다.

수치 공시는 인증된 OpenDART 원본파일 API의 해당 접수번호 XML에서 현행 모집 부분만 읽고, 이 경로가 실패하면 기존 DART 뷰어를 사용합니다. 원본 압축파일의 크기·항목 수·접수번호 파일명·CRC와 본문 크기를 검사하며, 파싱된 결과와 발표 대기는 접수번호별로 재사용합니다.

### 3. 실제 블로그 수집 점검
```bash
npm run collect:reviews -- --dry-run
npm run collect:reviews -- --stock iam-spac1 --write
```
기본 대상은 KST 청약 전날입니다. `--stock`은 정확한 종목 ID를 지정합니다. `--date YYYY-MM-DD`는 대상 선정일만 바꾸며 실제 수집 시각을 바꾸지 않습니다. `--write`는 로컬 JSON 저장이며 운영 배포를 뜻하지 않습니다. GitHub 워크플로 일정 설정은 매일 09:17·12:17·18:17 KST입니다. 실제 예약 실행, 스냅샷 커밋 권한, 해당 커밋의 배포 완료는 각각 확인해야 하며 설정 파일이 있다는 이유로 자동 갱신 완료를 주장하지 않습니다. Vercel 관리 화면의 수집은 미리보기로 응답하고 영속 저장 성공으로 처리하지 않습니다.

기존 `python_pipeline`은 웹 미연결 보관 코드입니다. 실제 블로그 수집과 운영 스냅샷 갱신에는 위 명령을 사용합니다.

## 💰 구글 애드센스 승인 체크리스트

1. 콘텐츠 수, 글자 수, 자체 점수나 면책 문구가 AdSense 승인을 보장하지 않습니다. 실제 승인 여부는 Google 심사 결과로만 확인합니다.
2. 기존8편 가이드의 URL을 유지하면서 잘못된 보장 표현을 정정하고 출처·계산 사례를 보완합니다. 종목 목록과 카드 누적을 유지하며 원문 확인 항목, 검토 전 등록자료, 계산 가정을 구분합니다.
3. 관리자 로그인은 기존 비밀번호와 호환되며, `ADMIN_SECRET`이 설정되어 있으면 그 설정값을 우선합니다. 실제 비밀번호는 문서에 기재하지 않습니다. Cron은 관리자 로그인과 별도로 `CRON_SECRET`의 Bearer 인증을 사용합니다.
4. `npm run test:content`, `npm run test:security`, `npm run build`로 검증합니다. 기존 금융 데이터 형식 검사는 원문 진위 검증을 뜻하지 않습니다.
